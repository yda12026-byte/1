# 题目 03｜个股多维诊断与证据验证

## 题目内容

请选择一只 A 股，设计并实现一个 AI Native 个股诊断产品。产品应帮助用户从经营质量、财务趋势、估值、行情特征、行业位置、重要事件与风险等维度理解公司当前状态，区分客观事实、分析推断与暂时无法验证的信息，并支持用户沿证据继续研究，而不是给出简单“好/坏”标签或买卖建议。

## 做题时间

**24 小时**

## 提交要求

1. 围绕核心任务完成可运行主链路：根据公司类型和用户问题选择诊断维度，并体现确定性指标计算、数据证据与 LLM 解读的合理分工。
2. 产品结果需体现：正面、负面、矛盾和未知证据的结构化表达；支持从诊断结论钻取到财务期次、行情区间、同行对比或待验证问题。
3. 提交可访问、可实际操作的 Web 产品 URL、源代码仓库及 README。
4. 提交 AI 使用与验证记录和测试说明；关键数字与结论必须可追溯。
5. 可选：提交 60–180 秒演示视频。

## 可使用的数据

扶摇：A 股与指数行情快照/历史 K 线、指数/板块成分、估值、财务、交易日历、涨跌停及热榜等特色数据；https://fuyao.aicubes.cn/docs/
iFinD MCP：可用的市场宽度、资金、宏观、政策、新闻和跨市场数据。
https://mcp.51ifind.com/?syncCookieTimes=1


## 统一规则

- **做题时间：24 小时。**
- **AI 工具与技术栈开放**，鼓励使用 AI Coding。
- 金融数据优先使用扶摇金融数据 API / MCP 与 iFinD MCP；能力以实际可调用工具为准。
- 不得在公开仓库提交 API Key、用户隐私或受限数据；涉及用户画像/持仓时应使用匿名或构造数据。
- 产品不得输出确定性涨跌预测、收益承诺或直接买卖建议；事实、推断与不确定信息必须区分。
- 核心结论必须能回到原始字段或原文，并明确来源、时点、单位及统计口径；数据缺失、冲突、过期或调用失败时不得静默生成“正常”结论。

## 最终交付物

### 必交
1. **可访问、可实际操作的 Web 产品 URL**（仅 PRD、PPT、Figma、截图不视为完成）。
2. **源代码仓库与 README**：说明启动方式、环境变量、产品选择、AI 的角色、数据来源、已知边界和未做事项。
3. **AI 使用与验证记录**：说明使用了哪些 AI 工具、AI 参与哪些环节、候选人修正了哪些错误或不合理结果。
4. **测试说明**：至少覆盖主链路、数据缺失/接口失败、极端或合规边界场景。

### 可选
5. **60–180 秒演示视频**：用于展示一名用户完成核心任务，建议直接演示产品，避免以讲 PPT 代替产品体验。
