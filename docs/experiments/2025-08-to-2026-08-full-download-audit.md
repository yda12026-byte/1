## 方式与保存边界

运行 `py scripts/download_annual_raw.py --source fuyao|ifind|official`。脚本按原始来源组下载，iFinD 日频/检索请求按月拆分并顺序调用，间隔 0.6 秒；已存在的成功文件不覆盖，失败留在审计中供重跑。原始 JSON/PDF 与逐项审计位于 Git 忽略的 `data/raw/annual-2025-08-31_2026-08-31/`，文档不公开受限数值、响应正文或授权信息。`py scripts/audit_annual_coverage.py` 将 72 条候选项映射到所需来源文件，但“文件齐备”不代表字段值、时点和口径有效。

## 下载结果

重试两项临时连接错误后，**19 份扶摇、128 份 iFinD JSON 和 5 份官方 PDF** 均保存成功或得到明确的无记录业务响应。扶摇 18 项为 HTTP 200、`code=0` 且有数据结构；除复权事件一项为 HTTP 200、`code=3002`（无匹配事件）。iFinD 128 项为 HTTP 200、内层业务 `code=1` 且有 `data`；这不保证自然语言结果中的每个指标都实际返回。原始响应文件的 SHA-256、请求参数和下载时点记在私有审计中。`data/raw/` 已由 `git check-ignore` 验证为 Git 忽略目录。

运行 `py scripts/audit_annual_coverage.py`：72 项候选中 **70 项有规划来源文件、仍需逐字段核准；1 项除复权事件源明确无匹配记录；1 项历史个股异动原因无可用回溯接口**。此分类是采集覆盖状态，不能等同产品字段的 `valid` 状态。

运行 `py scripts/check_annual_dates.py`，仅按返回的行日期审计：估值和行业各 366 个自然日行，其中各 105 个周末行，必须按交易日过滤；工业级碳酸锂与氢氧化锂各 261 个有日期行、锂精矿 248 行、碳酸锂期货 242 行。四类价格序列在单日首桶（2025-08-31）没有行；其余行的日期均落在各自请求月份。锂精矿序列有 6 个周末行，不能假定所有 EDB 序列都是交易日频。行数和日期检查不证明单位、品级、来源完整性或无历史修订。

## 已核对的边界

- 扶摇两只股票各返回 242 条前复权日线，实际交易日期为 2025-09-01 至 2026-08-31；起始日 2025-08-31 是非交易日。三张财报各取得多期响应，含比较基期；财务指标逐报告期请求。只有报告期在截止日之前且披露日可证实的行可进入产品证据。
- 扶摇个股异动原因能力只针对当日，不能回溯一年历史；当前候选字段 `f048` 在该窗口没有对应的历史来源。除复权事件请求如返回业务 `code=3002`，表示接口明确返回“无匹配事件”，需保留其原始状态，不当作所有公司行为不存在。
- iFinD 估值/行业/价格响应可能包含自然日而非交易日；公告和新闻搜索存在条数、相关性与原文缺口。所有日期必须再按窗口筛选；`get_stock_events` 的自然语言结果即使日期数量很多，也不可直接视作窗口内事件清单。
- 区间首日 2025-08-31 是非交易日。对这个单日发起的若干 iFinD EDB 请求，响应文本/指标元数据出现窗口外的旧日期和 2026-09 的日期，但结构化表没有该日数据；该单日桶不作为一年日频覆盖依据。日频覆盖从 2025-09 的实际交易日开始，原始响应仍保留供审计。
- 已取得五份公司官方定期报告原文：2025 半年报、三季报、年报及 2026 一季报、半年报。原文可用于核对分业务、产能、项目、减值与实际披露日；取得 PDF 尚不等于完成逐页核对。公告搜索片段仍不等于所有临时公告原文。
- iFinD 公司资料响应的文本日期还出现了 2026-08-31 之后的日期；仅凭请求写了“截至 2026-08-31”不能认定每行都符合截止日。
- 当前同行只有赣锋锂业这一候选样本，不能由此宣称“行业中位数”或完整同行组。2026-08-31 的历史估值也需核对返回日期、指标定义和负值处理，不混入下载当日的扶摇估值快照。

## 接手复核补充（2026-09-26）

第二会话接手后重新读取原始文件与审计，独立复核并补充以下事实；口径决定见[决策 0013](../decisions/0013-annual-data-approval-decisions.md)。
