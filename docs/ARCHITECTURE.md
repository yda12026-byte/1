# 架构草案

状态：初稿。主标的已定为天齐锂业（002466.SZ）；技术语言偏好已确定，具体 Web 框架、数据接口和部署方式以实际验证结果为准。

## 技术语言约定

HTML 前端可使用必要的 CSS 与浏览器 JavaScript。服务端、数据适配、指标计算、LLM 调用、辅助脚本和测试优先使用 Python；具体框架尚未选定。现有 Node.js 探测脚本和进行中的 `.mjs` 原型先保留，后续按工作树状态评估迁移或集成，不以语言偏好为由覆盖未提交改动。见 [`decisions/0004-python-default.md`](decisions/0004-python-default.md)。

## 用户主链路

选择预设个股与研究问题 → 根据公司类型及问题选择诊断维度 → 获取和校验数据 → 计算指标 → 生成带证据的诊断卡片 → 点击卡片查看财务期次、行情区间、同行对比或待验证问题。

## 模块边界

1. **数据适配**：接入可用的扶摇/iFinD 能力，保留来源、获取时点、原始字段、单位和口径。接口失败、缺失、冲突、过期均作为显式状态返回。
2. **确定性计算**：财务趋势、估值、行情等数字由代码计算，记录输入字段与公式；不让 LLM 生成或修改关键数字。
3. **证据组织**：将证据标为正面、负面、矛盾或未知；分别标明客观事实、分析推断及待验证事项。
4. **LLM 解读**：基于已校验的结构化证据解释含义和关系；输出需要有证据引用，无法支持的说法不展示为事实。
5. **Web 展示**：提供问题入口、诊断结果、证据钻取、数据状态与免责声明。
