# 0008：问题路由与候选字段配置

- 日期：2026-09-26
- 状态：已采纳，完整产品执行待实现

## 选择

将当前 72 条候选字段编成独立的 `config/diagnosis_fields.json`。每项保留稳定 ID、七维归属、来源表达、候选可用性、审阅限制和产品实现状态；可计算项另列公式 ID 与输入字段。`src/diagnosis/routing.py` 将问题归入固定意图，再展开维度和字段清单。多维提问保留所有识别出的维度；无法归类或索要直接交易建议的问题不取数。LLM 分类结果仅接受固定意图，失败时使用确定性关键词回退。

配置来自[当前候选表](../field-candidates-002466-v2.md)，可用 `py scripts/build_route_catalog.py` 重建并审阅差异。运行时读取独立配置，不依赖 Markdown。已取值仅表示实验阶段接口曾返回数据；路由中的 `product_state` 与 `execution_status` 分别表示字段和诊断能力是否已在产品实现，不等于证据 `quality.status=valid`。当前只有利润与经营现金流专项可执行，其余路由返回 `planned`，不读取快照或生成结论。

## 理由与替代方案

配置先于取数，使问题覆盖、字段缺口和证据依赖可审阅；可防止把 72 条候选项误当成已核准产品数据。相比让 LLM 自由挑选原始字段，固定意图和字段清单便于测试、复现及后续版本管理。相比把字段直接写死在提示词里，独立配置可逐项核对来源与公式。

## 影响与限制

当前字段 ID 随候选表顺序固定；若调整顺序，需审阅重建结果并更新已实现字段映射。关键词回退只用于有限问题，正式产品还须测试更多问法。计算清单中的未实现公式是待核准配方，不会自动产生数值；公告原文、同行组、估值与行情截止时点等仍需逐项落实。路由结果不能充当证据或结论。
