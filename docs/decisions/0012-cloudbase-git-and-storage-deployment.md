# 0012：CloudBase Git 构建与云存储快照

- 日期：2026-09-26
- 状态：方案已确定；云上构建、挂载与公开访问尚未实测

## 选择与理由

用户已购买 CloudBase 个人版，确定以 CloudBase 云托管运行 Python Web 服务，从 Git 仓库构建代码；已核准的固定产品快照单独放 CloudBase 云存储。服务运行时从云存储读取快照，不把受限数据放进 Git、镜像、构建产物或浏览器配置，也不在提问时调用扶摇/iFinD。

CloudBase 官方文档说明[云托管支持 Git 仓库部署](https://docs.cloudbase.net/run/deploy/deploy/deploying-git)，并可[挂载云开发对象存储为实例文件路径](https://docs.cloudbase.net/run/deploy/configuring/storage/cos)。本项目优先采用挂载路径：让现有 Python 快照读取器通过 `DIAGNOSIS_SNAPSHOT_PATH` 指向容器中的绝对路径，减少新的鉴权与下载代码。具体服务、环境、挂载和运行端口须以实际控制台配置与云上测试确认。

只上传核准后的发布快照，使用带版本/摘要的固定对象名；应用只读它，并校验快照版本、标的、内容摘要和时点。缺文件、挂载失败或校验失败时明确报不可用，不回退到仓库中的样本或未经核准的原始响应。用户提问产生的运行对象固定同一 `snapshot_id`。

云存储必须配置为不允许浏览器直接读取该快照；后端只返回诊断所需且获准展示的证据。CloudBase [存储权限文档](https://docs.cloudbase.net/storage/security-rules)说明客户端安全规则与服务端访问范围不同，且公开读取规则可能泄露数据。服务端凭据及 DeepSeek 密钥只放 CloudBase 的服务端配置，不进仓库或客户端。

## 替代方案与影响

不采用把快照提交到 Git、打入镜像或由前端直连云存储。服务端 HTTP API 下载也是可行的 Python 路径，但需要额外处理运行时鉴权、临时链接和缓存；本项目先按挂载方案实施，若实际环境无法挂载再新建决策记录调整。

后续必须完成：制作完整核准快照、确认云存储保存/展示许可、设置非公开权限与挂载、部署 Python Web 服务、验证构建日志和公开 URL、测试重启后读取同一快照及异常回退。当前仅有两字段旧快照和 CLI 诊断，尚无云上产品。
