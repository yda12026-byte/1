# 0015：可操作对话页面与 Python 接口

- 日期：2026-09-26
- 状态：已采纳（用户审阅 Codex 计划后，批准下述两项调整）

## 选择

- **框架与入口**：Flask 提供页面和 JSON 接口，云托管用 Gunicorn 运行 `webapp:app`，镜像只含 `src/`、`config/`、`web/` 与 `webapp.py`。接口为 `GET /healthz`、`GET /api/bootstrap`（标的、观察区间、示例问题、维度状态、快照状态）和 `POST /api/chat`（问题 + 上一轮受限意图上下文）。
- **状态语义**：`ok` 返回完整诊断运行对象；`not_implemented` 只列该路由的优先字段与证据缺口，不读快照、不给结论；`unsupported_question` 拒答买卖与涨跌预测；`clarification_needed` 要求补全问题；`snapshot_unavailable`（HTTP 503）表示快照缺失或校验失败，不用构造数据代替；非法请求为 400，超长请求体为 413。
- **有限追问**：只有“那现金流呢”“它们的比值呢”等固定短句可继承上一轮意图，且上一轮意图必须属于四个可执行意图；“它们”必须承接两项指标的问题。服务端不信任客户端上下文，其他指代（如“为什么”）一律要求补全，不交给 LLM 猜测。对话只保存在当前浏览器页面，不建账户或会话库。
- **LLM 分工调整（用户批准）**：规则路由已判出四个可执行意图之一时，不再调用 LLM 分类。原逻辑下 LLM 在这种情况只能确认、不能改变结果，却使每次提问多一次往返（实测约 10 秒以上）。模糊问法仍由 LLM 在固定意图白名单内分类；结论文案仍由 LLM 受限翻译。单次 LLM 超时由 20 秒降至 12 秒，使最坏情况留在 Gunicorn 45 秒超时之内。
- **文案回退修正（用户批准）**：实测四类问题的 LLM 文案全部因 `NO_LIVE_DATA` 回退，原因是模型把“不代表实时状态”“不能断言财务造假”等免责句复述进正文，被关键词校验命中。选择修改提示词：正文只陈述结论，不写限制与免责声明（页面单独展示“限制”），并列出正文禁用词；**不放宽**校验规则。

## 理由与替代方案

- Flask 足以支撑少量 JSON 接口和一个模板页面，依赖少，符合 Python 优先（决策 0004）；FastAPI 等需要额外 ASGI 运行时，对本产品没有收益。
- 追问也可交给 LLM 结合历史改写，但会引入不可审计的意图漂移；固定短句映射可以测试和解释。
- 也可放宽 `NO_LIVE_DATA` 只拦肯定句，但否定判断用正则难以可靠区分；收紧提示词不削弱合规边界。

## 影响

- 页面首版可诊断四类财务问题并钻取来源、报告期、口径、优先级、公式和输入证据；其余维度只显示字段缺口。完整快照与新维度接入同一接口和展示结构。
- 路由 `method` 对可执行问题记为 `deterministic_fallback`。
- CloudBase 云上构建、挂载与公开 URL 仍按决策 0012 待实测。
