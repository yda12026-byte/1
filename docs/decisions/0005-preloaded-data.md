# 0005｜预下载并发布数据快照

日期：2026-09-26

状态：已被 [0006｜考试固定快照](0006-fixed-exam-snapshot.md) 取代；保留原决策过程

## 选择

用户提问时不调用扶摇或 iFinD。独立下载任务从来源取数，完成字段、时点和口径校验后发布一个可追溯的快照；诊断只读取已发布版本。当前第一条“利润与经营现金流”切片将两项扶摇年报字段写入本地、被 Git 忽略的 `data/cache/`，发布时使用临时文件和原子替换。每次诊断记录快照 ID 与下载时间。

后续部署把快照和标准化证据存到服务器端数据库，保留同一读取接口。iFinD 数据在相应维度的字段映射及口径核准后由下载任务加入；当前 Python 脚本仅验证 iFinD 接口能力，尚未下载其产品字段。

## 理由

提问路径只读本地已校验数据，响应时间不受金融接口波动影响，且同一快照下的数字与结论可复现。下载失败不会替换上一版；快照超过当前年报样例的七天阈值时，证据标为 `stale`，结论转为未知，不把旧值包装成最新值。

## 替代方案与影响

原先每次运行 `diagnose_profit_cash.py` 都直接调用扶摇；现改为先运行 `download_data.py`，诊断脚本不持有金融数据 API 凭据。当前快照只保存选定的标准化字段，不保存完整受限响应，也不提交 Git。之后的行情、估值、事件和公告需要分别制定下载频率、时效阈值及原文定位；公开部署前须确认数据授权允许服务器保存与对外展示。

服务器数据库建议至少分为下载批次、标准化观测值、来源定位与当前发布版本。发布指针只能在同一批数据通过校验后切换，诊断运行需固定使用一个版本；数据库产品和部署平台尚未选定。
