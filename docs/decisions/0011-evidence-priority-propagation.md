# 0011：四档优先级进入证据与结论对象

- 日期：2026-09-26
- 状态：已采纳；目前覆盖四个已实现的窄财务意图

## 选择与理由

延续[决策 0010](0010-company-specific-display-priority.md)的公司专属四档配置。每条已实现的来源或计算 `Evidence` 都保存 `priority`：`field_id`、`tier`、`reason`、`profile_version`；`Conclusion` 同样保存优先级。净利润、经营现金流、两者比值和方向关系分别映射到 `f021`、`f022`、`f024`、`f066`。这使运行记录离开路由配置后，仍能说明为何某项证据被优先展示或解读。

计算证据还按输入证据 ID 保存输入优先级快照，并校验引用一致。计算输出按自身字段配置定级；优先级供后续计算编排和证据组织参考，不是公式系数。当前比值仍只按有效性、期间、口径和非正分母规则计算，不受优先级改变。

受限 LLM 翻译接收证据与结论的优先级，优先解释有效的高优先级证据。高优先级字段缺失时保留未知状态；`cannot_say`、事实锚点和引用校验继续约束输出。优先级不是数值评分，也不能把弱证据变成事实。

## 替代方案与影响

仅在路由 `display_plan` 保存优先级，会让独立运行对象失去解读依据；给财务公式引入权重则会改变指标定义。因此把优先级作为可追溯元数据，并把数值计算与证据质量校验分开。

后续新增字段适配器时必须明确字段 ID、配置版本、计算输入优先级来源，并测试缺失与冲突状态。当前仅四个窄意图生成完整运行对象；七维中其余字段的优先计算编排、真实数据适配和 Web 展示仍待实现。
